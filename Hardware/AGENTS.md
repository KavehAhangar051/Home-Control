# ترجیحات کلی پروژه و قوانین کار با RTK (Lite Mode)

## ۱. ابزار بهینه‌سازی توکن (`rtk` - Rust Token Killer | Lite Mode)
- ابزار **`rtk` (`v1.2.1`)** روی حالت **Lite Mode** (تمدید `rtk:default` و `rtk:terse` در `.rtk/pipeline.toml`) در این مخزن پیکربندی و فعال است.
- **اجرای یکپارچه دستورات شل با `r`:** تمام دستورات ترمینال (`git`، `grep`، `rg`، `find`، `ls`، `diff`، `curl`، `npm`، `bun`، `tsc`، `test`، `build` و...) را حتماً از طریق یکی از روش‌های زیر اجرا کن:
  - `bun run r -- <cmd>` (یا `npm run r -- <cmd>` یا `bash ./tools/r <cmd>`)
- این wrapper قبل از هر دستور:
  1. در صورت ریست شدن کانتینر AI Studio یا ایمپورت جدید از گیت‌هاب، به‌صورت خودکار باینری `rtk` و symlinkهای `$HOME/.config/rtk`، `$HOME/.local/share/rtk` و `/usr/local/bin/rtk` و مجوز `+x` اسکریپت‌ها را بازیابی می‌کند.
  2. دستورها را به‌صورت شفاف از طریق `rtk` اجرا و خروجی‌های حجیم را در Lite Mode فشرده می‌کند و آمار را در دیتابیس دائمی ذخیره می‌نماید.
- **حفظ دائمی داده‌ها و تنظیمات:** باینری کش‌شده، فایل تنظیمات Lite Mode (`config.toml`, `pipeline.toml`) و دیتابیس تاریخچه (`history.db`) همگی در مسیر `<repo>/.agent-state/rtk/` نگهداری می‌شوند تا در چت‌های جدید، ریست کانتینر، و حتی حذف پروژه و ایمپورت مجدد ریپازیتوری از گیت‌هاب از بین نروند.
- **دستورات مفید RTK:**
  - بازیابی خروجی کامل بریده‌شده: `rtk recall <hash>`
  - اجرای بدون فیلتر در موارد خاص: `rtk bypass <cmd>`
  - مشاهده آمار صرفه‌جویی توکن: `bun run rtk:gain` (یا `npm run rtk:gain`)
  - بررسی سلامت کامل ابزار و symlinkها: `bun run tools:check` (یا `npm run tools:check`)
  - راه‌اندازی/بازسازی دستی در صورت نیاز: `bun run rtk:setup` (یا `npm run rtk:setup`)

## ۲. نحوه پاسخ‌گویی و استاندارد کد
- خلاصه، دقیق و صادق باش؛ از اغراق، تکرار و توضیحات اضافه پرهیز کن.
- برای ویرایش‌های محدود، کل فایل را بازنویسی نکن. هرگز `.env` یا `.agent-state/rtk/data/history.db` را حذف نکن.
- کارهای مستقل (خواندن/ویرایش فایل‌ها) را موازی انجام بده.
- پیش از تحویل تغییرات کد، `lint` / `typecheck` / `build` را از طریق `r` اجرا و بررسی کن.
