# ترجیحات کلی

## نحوه پاسخ‌گویی و شروع کار
- خلاصه، دقیق و صادق باش؛ از اغراق، تکرار و توضیحات اضافه پرهیز کن.
- برای ویرایش‌های محدود، کل فایل را بازنویسی نکن. هرگز `.env` را حذف نکن.
- فایل `ARCHITECTURE.md` را هنگام تغییر کد، معماری یا ناوبری بخوان (برای پرس‌وجوهای ساده نیازی به خواندن کامل آن نیست).

## قبل از کدنویسی و استاندارد کد
- **Think Before Coding:** فرضیات و ابهام‌ها را پیش از اجرا مشخص کن؛ راه‌حل ساده‌تر را ترجیح بده؛ کارهای مستقل (خواندن/ویرایش فایل‌ها) را موازی انجام بده.
- **Simplicity & Surgical Changes:** حداقل کد لازم برای حل نیاز کاربر؛ بدون قابلیت ناخواسته، abstraction تک‌باره، یا refactor غیرمرتبط؛ فایل‌ها را ماژولار و خوانا (~۲۰۰–۳۰۰ خط، سقف ~۴۰۰ خط) نگه دار و برای توابع پیچیده توضیح استاندارد بنویس.
- **Skill Selection:** فقط وقتی کاری واقعاً به مهارت تخصصی نیاز دارد به `agents/skills/SKILLS-GUIDE.md` رجوع کن و مهارت مرتبط را با قوانین پروژه تطبیق بده؛ در کارهای عادی این فایل حجیم را بیهوده نخوان.

## ابزار بهینه‌سازی توکن (`rtk`)
- **اجرای یکپارچه شل با `bun run r -- <cmd>`:** تمام دستورات ترمینال (`git`، `grep`، `bun run lint/typecheck/test/build`، `diff` و...) را از طریق **`bun run r -- <cmd>`** (یا `bash ./tools/r <cmd>`) اجرا کن تا هم مجوز `+x` حفظ شود، هم خروجی‌های حجیم با `rtk` (`mode Lite`, `v1.2.1`) فشرده و در `.agent-state/rtk/data/history.db` ثبت شوند (`tsc/biome/test/next` خودکار به فیلتر بومی نگاشت می‌شوند). برای متن کاملِ بریده‌شده از `rtk recall <hash>`، برای آمار از `bun run rtk:gain` و برای بررسی سلامت ابزار از `bun run tools:check` استفاده کن.

## بعد از هر تغییر و معیار کیفیت
- **بیلد یک‌باره در پایان کار:** حین ویرایش فایل‌ها هیچ بیلد یا رندر میانی برای Preview اجرا نکن؛ فقط **یک بار در انتهای تمام تغییرات** بیلد نهایی را بگیر تا ترافیک اینترنت مصرف نشود.
- **Verification:** پیش از تحویل، `lint` (`biome`)، `format` و `typecheck` را اجرا کن و خروجی واقعی را بررسی کن (فقط به exit code بسنده نکن؛ هر بخش غیرقابل تست را صریحاً اعلام کن).
- **مستندسازی:** پس از تغییرات معنادار در کد، ساختار یا رفتار، مستندات مرتبط (`ARCHITECTURE.md`، `README.md`، `DESIGN.md`، `docs/*`) را همان‌جا بروزرسانی کن.
- **ممنوعیت‌ها:** هیچ تست موقت، تزئینی یا تست UI (کلاس Tailwind، پیکسل، انیمیشن، چیدمان) ننویس؛ تست جدید فقط با درخواست صریح کاربر برای منطق حیاتی دامنه/پروتکل. استفاده از `playwright` / `playwright-cli` مطلقاً ممنوع است. فایل‌ها و اسکرین‌شات‌های موقت بررسی را پاک کن.
