# Design System — Home Control Dashboard

## Product and UX direction

Home Control Dashboard is a Persian-first control surface for ESP32 home automation. The interface should feel like a focused product workspace: calm, operational, and predictable under frequent use.
Use ChatGPT and Cloudflare Dashboard as interaction references, not as assets or exact copies. Prefer clear hierarchy, restrained chrome, subtle separators, consistent spacing, and controls whose state is immediately understandable.

## Navigation and header

- On desktop (`md` and above), navigation uses a vertical rail on the right side of the viewport, consistent with the application's RTL direction, paired with a bottom desktop footer bar.
- On mobile (`< md`), the right rail, desktop footer, header `MacroSidebar`, and header `ThemeToggle` are hidden; navigation uses a centered floating bottom Dock with upward-expanding `ExpandableTabs` panels (`MobileDockNav`) supporting downward swipe-to-dismiss, an upward `"macros"` tab for all custom buttons, and an integrated press-and-hold voice command trigger, while mobile theme switching (`حالت روز` / `حالت شب`) lives at the top of `Settings → شخصی‌سازی داشبورد` (`ColorsSection.tsx`, `md:hidden`).
- On desktop (`md:`+), custom buttons / macros live inside the top `DashboardBreadcrumb` header next to `WorkspaceViewModeSelector` as a compact quick-run button or anchored dropdown selector so Grid, Trellis, and Canvas remain unobstructed.
- Every submenu entry (`Modules`, `Automations`, `Settings`) pairs its Persian label with a semantic Lucide icon across desktop sidebar submenus, mobile Dock upward panels, mobile subsection tabs, and breadcrumbs.
- Status notifications (`ToastNotification`) render as compact single-line pills anchored in the top header band inside a `pointer-events-none` wrapper with click and upward swipe-to-dismiss so they never cover segment cards or block clicks on mobile or desktop.
- In Trellis workspace mode, `TrellisChromeBar` exposes three built-in presets (`نمای گروه‌ها`, `پنل دیواری`, `همه قطعات`) plus a `چیدمان‌ها` popover for saving, restoring, and deleting named custom panel arrangements locally.
- Do not expose header-position switchers or controls that move desktop navigation to another edge.
- Preserve existing application actions and behavior when adjusting navigation. Presentation changes must not alter MQTT topics, ESP32 payloads, Cloudflare synchronization, or automation logic.
- The product title may remain editable, but it must not control header placement.

## Color and appearance

- Default appearance starts in dark mode (`Graphite` neutral ramp `#141415` rendered immediately on `<html>` via SSR `dark` class + synchronized `.dark`/`.light` classes and `<meta name="theme-color">` inside `DashboardStyles.tsx`) and supports user switching to light mode through `ThemeToggle` using the native View Transition API with a reduced-motion fallback.
- `app/globals.css` (`:root, .dark` and `.light`) and `themeStyles.ts` align ReUI design tokens (`--background`, `--card`, `--sidebar`, `--primary`, `--primary-foreground`, `--secondary`, `--border`, `--muted-foreground`) with custom dashboard tokens (`--bg-main`, `--card-bg-solid`, `--border-color`, `--text-*`, `--accent3`, `--accent3-dark` via `computeAccentHoverHex`, `--accent4`, and `*-foreground` pairs) so every screen renders uniformly in both dark and light modes, with Light Mode separating sidebar/header/footer chrome (`#f3f3f5`) cleanly from the main canvas (`#f8f8fa`) and scoping white top-edge inset highlights strictly to `dark:`.
- Settings expose controlled customization for primary/secondary accents (`accent3`, `accent4`) and dark/light contrast balance (`darkBlackness`, `lightWhiteness`); active (`1`) output and input segments, all 6 beUI motion sliders (`RangeSlider`, `InlineSlider`, `FluidSlider`, `BubbleSlider`, `WaveSlider`, `RulerSlider`), `WelcomePortal`, `LowDataModeBanner`, and settings toggles/editors share unified `accent3`/`accent4` and semantic `*-foreground` contrast pairs, while input segments remain clearly distinguished via a read-only `ورودی` footer badge.
- Prefer neutral surfaces, restrained borders, and readable contrast across active, pending, disabled, and error states (retaining high-contrast `text-amber-800 dark:text-amber-300` on soft warning surfaces in `PinSelector.tsx`). Do not rely on color alone to convey device state.
- When `data-perf-tier="lite"` or `animationsFps=30` is active on resource-constrained devices, multi-layer `backdrop-blur` and expensive per-frame filters step down cleanly to crisp solid surfaces without flattening state hierarchy.

## Typography

- **Dana** (`--font-dana`, bundled locally via `next/font/local` with Persian `FaNum` glyphs) is the default UI font.
- Five selectable secondary fonts (`Vazirmatn`, `IBM Plex Sans Arabic`, `Noto Sans Arabic`, `Rubik`, `Readex Pro`) are configured in `app/layout.tsx` (`preload: false`) and managed through `lib/fonts.ts` so users only fetch non-default webfonts when chosen.
- Use a consistent type scale (`text-fluid-*` / tabular numbers for telemetry and counters). Keep Persian labels concise, direct, free of raw Markdown punctuation or translationese shells, and consistent on «قطعه» (rather than mixing «سگمنت» and «ماژول») across user-facing controls and hints.

## Layout and responsive behavior

- The root document uses Persian language and RTL direction.
- Keep the right rail distinct from the workspace with spacing and a subtle border/surface difference rather than heavy shadows.
- The workspace must remain usable at desktop, tablet, and mobile widths. Group cards (`@container/group`), Trellis panels (`@container/trellis-group`), segment cards (`@container/segment`), and Settings/Workspace containers (`@container/workspace`, `@container/settings-card`) adapt directly to their own container width via Tailwind CSS v4 container queries. On narrow screens, keep navigation reachable and compact; do not fall back to a top header.
- Prefer consistent spacing and concentric corner radii (`bezel-core` = `R1 − B − S6 = 13px` inside `bezel-shell` `20px`; switch thumb = `R_track − B − pad = 4px` / `3px`). Detailed monochrome engineering dimensional drawings live in `docs/dimensional-drawings/` (`UI-SEG-001`, `UI-DOCK-001`, `UI-GRP-001`). Use cards only when grouping content improves scanning or task completion.

## Interaction and accessibility

- Use semantic buttons, accessible names for icon-only controls, visible keyboard focus, and appropriate disabled/pending states.
- Distinguish a requested command from confirmed device state when MQTT, WebSocket, or Cloudflare communication may fail: segment tiles paint instant optimistic feedback via React 19 `useOptimistic` with a subtle pulsing indicator while awaiting confirmation and automatic rollback on failure, and flash a brief green ACK ring (`700ms`, `bg-success ring-4 ring-success/35`) solely on the card's status dot when ESP32 `command_ack` arrives (`pinAckBus` / `usePinCommandAck`) without flipping switch or dimmer state.
- Subtle mobile haptic feedback (`lib/haptics.ts` via Web Vibration API, calibrated with `>= 22ms` pulses and single-pulse fallback for AOSP/Motorola vibrator HALs) and gesture-unlocked Web Audio (`lib/audio/{context,effects,index}.ts`, with silent hardware priming and mobile gain calibration) reinforce segment toggles, push presses, macro execution, voice push-to-talk, and toast alerts, while remaining user-controllable in Stability/Audio settings (`HapticsToggle`).
- Stability settings (`BackupRestoreSection`) and Workflow Studio (`WorkflowHeaderBar`, `WorkflowFooterControls`) expose direct JSON backup/export, restore/import, and native sharing (`File System Access API` + `Web Share API` with graceful download/input/clipboard fallbacks), alongside Workflow Studio Undo/Redo (`Ctrl+Z`/`Ctrl+Y`), Copy/Paste/Duplicate (`Ctrl+C`/`Ctrl+V`/`Ctrl+D`), and Sub-flow container grouping (`Ctrl+G`).
- First-run permission & cookie consent (`PermissionsOnboardingModal` + `Stability → PermissionsStatusCard`) lazily presents a single-elevation RTL `bezel-shell`/`bezel-core` setup dialog when `hc_permissions_consent_v1` is absent, capturing Storage persistence, Microphone, Web Audio unlock, background Notifications, and optional Screen Wake Lock inside a single user gesture with essential-only fallback and zero decorative pills.
- Preserve rich Motion springs, transforms, opacity transitions, and View Transitions by default; adaptively step down GPU-heavy filters and continuous ambient loops on struggling devices while never blocking essential interaction feedback.
- **Canvas Sheet & Workflow Studio spatial motion (`sheetViewportAnimator.ts`, `useSheetViewportGestures.ts`):** Moving across the infinite Canvas Sheet (`CanvasWorkspace` and `WorkflowStudio`) stays strictly locked under the user's finger on touch devices (`10px` touch threshold, zero post-lift touch inertia drift, `90ms` / `18px` post-pinch settle guard, `overflow-clip` scrollport lock against browser focus jumps, and directional `scroll-child` handoff inside scrollable groups), while desktop mouse drags retain momentum inertia coasting, smooth spring-interpolated focal wheel/button zoom, and cubic-out camera flight (`Fit View`, `Reset Layout`) imperatively on `worldPlaneRef`. On touch, only `<GripHorizontal>` handles initiate node drag (`10px` threshold), selection waits for a clean header tap, and `useSegmentButtonProps` / `pointer-fine:active:scale-*` prevent accidental touch misfires, haptics, or scale twitches.
- **Analog PWM dimmer cards & rules (`AnalogOutputBody`, `AddSegmentForm`, `ConditionActionItem`):** `analog_output` segments share the unified `accent3` active visual language across Grid, Trellis, and Canvas, pairing a tactile Power keycap (`0x01`, restoring last non-zero intensity) with a `DashboardSlider` (`0x0A`, 100ms drag throttle + immediate release flush) and tabular `%` telemetry, while the Modules form provides recommended PWM pin quick-picks and resolution/frequency presets and the Conditions editor toggles between boolean mode and exact PWM duty sliders.
- **Adaptive beUI Motion Sliders (`DashboardSlider`, `SliderStyleSection`):** Every slider in the dashboard renders through the 6 beUI motion primitives (`InlineSlider`, `RangeSlider`, `FluidSlider`, `WaveSlider`, `BubbleSlider`, `RulerSlider`). By default (`auto`), each surface uses its most ergonomic design (`Fluid` on PWM cards, `Inline` in appearance tuning, `Ruler` on Auto-Off timers, `Bubble` in segment creation, and `Range` in rule editors), and users can switch all dashboard sliders globally to any of the 6 models with a live interactive preview inside Settings → Appearance.
- **Multi-step forms (`ProgressSteps`) & anti-drift design rules (`components/motion/progress-steps.tsx`, `AddSegmentForm`, `AutomationForm`, `MacrosSection`, `AuxNodeModal`):**
  - Multi-section creation/configuration forms (`افزودن قطعه جدید`, `افزودن اتوماسیون جدید`, `ساخت دکمه سفارشی`) break decisions into 2–3 focused steps driven by the shared Dissolve-inspired `ProgressSteps` stepper (RTL numbered track, one-shot DPR-scaled particle-grain progress stream with zero idle CPU, spring checkmark reveal on completion, direct jump navigation for unlocked steps, and full `animationsEnabled` / `prefers-reduced-motion` / `data-perf-tier="lite"` compliance).
  - Hide specialist hardware parameters (`تنظیمات تخصصی PWM`, `تنظیمات تخصصی سنسور ADC`) behind progressive-disclosure accordions while surfacing recommended GPIO quick-picks, visual type cards, and plain Persian descriptions upfront for everyday users. Never expose raw protocol opcodes (such as `0x0F`) or internal jargon in user-facing buttons or helper text.
  - **Strict icon, contrast & surface law:** Import UI icons from the canonical HugeIcons groups (`components/ui/hugeicons-groups/{shell,controls,media,welcome}.tsx`) rather than ad-hoc `lucide-react` imports; pair every `bg-accent3`, `bg-accent4`, and `bg-destructive` surface with its semantic `*-foreground` text token (never `text-white` or `text-bg-main`); use a single `bezel-shell` > `bezel-core` elevation per form (separate inner groups with spacing and hairline dividers rather than nested boxes); avoid decorative static pill badges above headings (`WorkspaceSection`); and use «قطعه» consistently everywhere instead of mixing «سگمنت» / «ماژول».
- Respect both `animationsEnabled` and `prefers-reduced-motion` (`MotionConfig reducedMotion`). Sound and haptics must never be required to understand or complete an action.
- **Impeccable craft, touch & RTL hardening (`themeStyles.ts`, `baseStyles.ts`, `reui-nova.css`, `use-slider.ts`, `color-picker.tsx`, `lib/persianText.ts`):** Technical badges, GPIO pins, timers, and logic gate labels keep tabular monospace (`--font-mono`, excluded from the Persian sans override); `.cn-alert` uses logical RTL properties (`text-start`, `pe-18`, `end-2`); `touch-none` is scoped strictly to drag handles (`GroupHeader`, `CardHeader`, `PlaceholderCard`, and Canvas `<GripHorizontal>` grips) so mobile page scrolling and Canvas panning never stall over cards; sliders and the color picker isolate active `pointerId` and recover cleanly on `lostpointercapture` / `window` `blur`; hover rules gate on `@media (hover: hover) and (pointer: fine)`; active press scales on interactive cards gate on `pointer-fine:`; keyboard `focus-visible` rings and single-`<h1>` landmark hierarchy hold across all views; and GPIO input / Workflow search normalize Persian/Arabic numerals (`۰-۹`/`٠-٩`) and `ي`/`ك` variants while preserving ZWNJ (`\u200C`).

## Implementation boundaries

- Root layout and global font loading: `app/layout.tsx` and `app/globals.css`.
- Desktop right-rail header/navigation (`md:`+): `components/MasterHeader.tsx` and `components/MasterHeader/`.
- Mobile floating Dock navigation (`< md`): `components/motion/{dock.tsx,expandable-tabs.tsx,expandable-tabs-layout.ts}` and `features/dashboard/components/layout/MobileDockNav.tsx`.
- Shared multi-step form stepper: `components/motion/progress-steps.tsx`.
- Dashboard composition: `features/dashboard/components/layout/` (`DashboardHeader.tsx`, `DashboardBreadcrumb.tsx`, `DashboardMain.tsx`, `MobileDockNav.tsx`).
- Shared dynamic CSS: `features/iot/components/DashboardStyles.tsx` and `features/iot/components/styles/`.
- Settings UI: `features/settings/components/SettingsDrawer/`.
- Keep styling local to the owning component unless it is a genuine shared token.
- Make surgical changes: redesign navigation or appearance controls without refactoring unrelated dashboard, device, or automation features.
- **Documentation & verification discipline:** Update `DESIGN.md` (and `ARCHITECTURE.md`) immediately after any UI, layout, or token change so this guide stays accurate and trustworthy. Do not write unit tests for UI styling, Tailwind classes, pixel layouts, or animations.
